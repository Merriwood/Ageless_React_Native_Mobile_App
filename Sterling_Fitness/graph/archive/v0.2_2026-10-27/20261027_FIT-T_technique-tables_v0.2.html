Rules

  1. Log by exercise. Score the program by exercise. Check and report targets by body part.
  2. Each exercise has a permanent id. Never match logs by name.
  3. Compare weight and progress only within the same exercise (ST4).
  4. Code builds the program from written rules (N3). A language model never does.
  5. The member approves the program before it starts (G1).
  6. Score against the program. Every program meets the targets, so a member who falls short of the program scores lower.
  7. Only the assigned exercise counts toward the program score. A substitute is logged and counts toward the target report, but earns no program score.
  8. A program change starts on a Sunday. Each week is scored against the program version in force that week, and the score stores that version.
  9. Every movement and exercise needs a published source before it ships.

ST1 · Training Volume & Muscle Balance (ages 50-64 · 65+)

Scores how much of the week's program the member did, and reports whether each body part got enough strength work, often enough, for the member's age band. One agent for all ages: only the target changes, and N1 supplies the band.

Deviations: where the code differs

IdAgentDetail
D1ST1The fitness_analytics.py docstring describes a 'hard set' rule (3 or fewer reps in reserve, or at least 60% of estimated 1RM). The code counts every logged set, because the app records no weight or effort. Fix: reword the docstring to match the code. Weight and effort belong to ST4.
D2ST1Training days per body part (ST1.4) are not counted or scored.
D3ST1The weekly targets in the code are one placeholder table for every age (legs 10, push 8, pull 8, core 5), with no source. Decided: 6 a week per body part, push and pull 6 each, limit 9 (O1, O2, O4).
D4ST1Squats and push-ups are logged but skipped by the code (EXCLUDED_EXERCISES). The exercise model counts them.
D5ST1The scoring code uses four groups (lower_body, upper_push, upper_pull, core) and averages four. The model has three body parts (legs, upper_body, core).
D6ST1The scoring code matches logs by the app's names (e.g. 'Military'), not by id. Switch matching to ids before any app name changes, or logged sets stop counting.
D7ST1The scoring code scores sets against targets (ST1.6). The method scores the program (ST1.5). Until the code changes, the strength score is the target score, and no program is stored.
